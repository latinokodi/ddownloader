# SPEC — parity matrix (the Electron app · Electron → Android)

**Corrected premise (owner, 2026-10-26):** "tor" in this project means **TorBox**, the debrid
service — not the Tor anonymity network. The original app contains no onion-routing code
(verified: zero hits for `socks|onion|torproject|9050|arti` across `electron/` and `src/`, see
`docs/source-analysis.md` §6). Tor-network scope that the brief assumed was therefore removed
from the port; the "leak-free" requirement is interpreted where it actually applies — API
credentials, tokens in logs, and data at rest. See `DECISIONS.md` Decision A for the full
correction and the evidence that drove it.

**Baseline:** `F:\PyApps\tordownloaderElectron` working tree at commit `1f70fd4` plus uncommitted
changes and the 2026-10-26 Comet add-on replacement (marked *LEAD MODIFICATION*). SHA-256 of every
cited source file is pinned in `docs/source-analysis.md` §0.

| status | meaning |

## 3. Deliberate divergences from the desktop behaviour (all in the safe direction)

1. **Truncated-partial publishing (P16b).** Electron's worker treats a CDN that ignores `Range`
   as "the file is complete" and marks a short file done. The port discards the partial and
   re-fetches from zero, then verifies the size — demonstrated in scenario s3.
2. **Redirect allowlist (P38).** Validation moved from the first URL to every hop.
3. **Secret handling (P02).** Plaintext SQLite + renderer exposure replaced by keystore ciphertext
   and presence flags.
4. **Logging (P02a).** The desktop leaks bearer tokens through `AxiosError` serialisation; the
   port redacts before buffering.
5. **`If-Range`.** Added so a resume after the remote object changed restarts instead of appending
   to a different representation.
6. **Status model (P40).** Free-text status strings that embedded signed URLs became a structured
   enum, so no credential-bearing URL is ever persisted.
